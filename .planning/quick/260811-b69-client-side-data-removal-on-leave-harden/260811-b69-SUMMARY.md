# Quick Task 260811-b69: Harden client-side data removal on leave

Widened the on-leave wipe from a `ketcher`-prefix localStorage sweep to every
browser store the page can reach, added an opt-in Clear-Site-Data purge for the
~29 MB HTTP cache, and made the privacy policy state honestly what is and is
not removed.

## What changed

**Task 1 — `src/lib/leaveWipe.ts` (renamed from `clearEditorStorage.ts`).**
`EDITOR_STORAGE_PREFIX` and the collect-then-remove loop are gone; the module
now exports `LEAVE_NO_TRACE_KEY`, `isLeaveNoTrace()`, `setLeaveNoTrace()`,
`wipeSiteData()`, `registerLeaveWipe()`. `wipeSiteData()` calls
`localStorage.clear()`, read-clear-restores sessionStorage around the single
opt-in flag, and fires two unawaited, `.catch()`-swallowed sweeps (IndexedDB
`databases()` → `deleteDatabase`, Cache Storage `keys()` → `delete`). Service
workers are unregistered only under `window.crossOriginIsolated`.
`registerLeaveWipe()` still listens on `pagehide`, queues the beacon first when
the flag is on, then wipes. Import in `src/main.tsx` updated; registration
stayed in `main.tsx` for the reason its comment gives.

**Task 2 — leave endpoint + footer toggle.** `nginx.conf` gained an exact-match
`location = /explain-that-inchi/__leave` returning 204 with
`Clear-Site-Data: "cache","storage"` and both isolation headers repeated.
`SiteFooter` gained one `useState(() => isLeaveNoTrace())` and a `<label>`-wrapped
checkbox ("Leave no trace on exit") between the logo and the legal links, with
the reload and Safari caveats in a `title`. `.site-footer-toggle` added beside
the existing global footer rules — no CSS module, no new dependency.

**Task 3 — privacy policy.** § 3 (2) narrowed to "none of this data remains
stored on your device between visits". New (3) states the HTTP cache and
browsing history survive leaving and that a website can never delete history.
New (4) describes the opt-in: off by default, per-visit, asks the browser to
clear cached files and stored data on leaving, with both limitations (reload
indistinguishable from close → ~29 MB re-download; Safari does not support
Clear-Site-Data) and a note that history is never affected. Version bumped to
11.08.2026. Five new pinning assertions in `legalContent.test.ts`.

## Deviations from plan

**1. [Rule 3 — blocking] Guard style: property access, not `in window`.**
The plan specified `'indexedDB' in window && typeof indexedDB.databases === 'function'`.
That form breaks in the "capability absent" test case: once a test defines
`window.indexedDB = undefined`, `'indexedDB' in window` is still true and
`indexedDB.databases` throws a TypeError. Used `typeof window.indexedDB?.databases
=== 'function'` and `if (window.caches)` instead. Both satisfy the plan's actual
requirement — the hazard is a *bare identifier* read (`caches` alone is a
ReferenceError on insecure origins), and a `window.`-qualified property access
never is. Commented as such in the source. Commit 02535ca.

**2. Stale comment fixed in Task 1 rather than Task 3.** The plan put the
`clearEditorStorage.test.ts` filename fix in `legalContent.test.ts` under Task 3;
it was moved into Task 1 because Task 1's `<done>` requires
`git grep clearEditorStorage -- src` to return nothing. Same edit, one commit earlier.

**3. Baseline test count was 526, not the 520 the plan states.** No tests were
removed; the count rose 526 → 546 (+20). The old wipe test's
delete-while-walking regression case was replaced, per the plan, with a case
proving a non-prefixed key is now removed.

**4. Two extra tests beyond the plan's `<behavior>` list.** `SiteFooter` starting
checked when the flag is already set, and the flag clearing on uncheck — both
cheap, both guard the round-trip the footer actually performs.
