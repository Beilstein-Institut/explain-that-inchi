<objective>
Harden the on-leave client-side data removal and add an opt-in full-cache purge.

Purpose: the privacy policy promises data is gone when the visitor leaves. Today
that promise covers a `ketcher`-prefixed localStorage sweep and nothing else.
Widen the wipe to everything the site can actually reach, offer an opt-in
Clear-Site-Data purge for the ~29 MB HTTP cache, and make the legal text state
honestly what is and is not removed.

Output: a renamed, widened wipe module; an nginx leave endpoint; a footer
toggle; updated legal text; tests pinning all of it.
</objective>

<measured_baseline>
Measured with a throwaway Chromium profile (fresh profile, one visit, SIGKILL so
the existing pagehide wipe never ran). Ground truth — do not re-derive:

- HTTP cache: 119 MB dev / ~29 MB prod, `public, max-age=31536000, immutable` (nginx.conf:43)
- localStorage: `ketcher-opts`, `ketcher_editor_saved_settings` (+ `ketcher-tmpls` after a favourite)
- Code Cache (compiled JS/WASM): 36 KB
- sessionStorage: EMPTY — the coi-serviceworker keys are never written
- IndexedDB: none. Cookies: none.
- Service Worker registration: NONE — coi-serviceworker.js returns early because
  COOP/COEP already arrive from the origin.
- History / DIPS: present and unreachable by any site-side code.

The IndexedDB and Cache Storage sweeps in Task 1 therefore clear nothing today.
They are a guard against a future dependency introducing a store, matching the
rot-prone reasoning already documented in the current file header.
</measured_baseline>

Exports: `LEAVE_NO_TRACE_KEY`, `isLeaveNoTrace()`, `setLeaveNoTrace(on: boolean)`,
`wipeSiteData()`, `registerLeaveWipe()`.

Delete `EDITOR_STORAGE_PREFIX` and the collect-then-remove sweep loop entirely
and call `localStorage.clear()`. This is both simpler and stronger: the app
persists nothing of its own, so there is no key worth preserving, and the
version-rot problem the old header describes disappears with the loop. Drop the
`store: Storage` parameter too — the function now clears both stores, so it has
nothing left to parameterise.

sessionStorage: read the flag value, `sessionStorage.clear()`, write it back if
it was present. Read-clear-restore, not a key-collection loop.

Best-effort async sweeps, each guarded and each `.catch()`-swallowed, fired
without awaiting (pagehide gives no time to await):
- `'indexedDB' in window && typeof indexedDB.databases === 'function'` →
  `databases()` then `deleteDatabase(name)` for each named entry.
- `'caches' in window` → `caches.keys()` then `caches.delete(k)` for each.
Use `in window` guards, not bare identifier reads: `caches` is undefined on
insecure origins and a bare read is a ReferenceError, not undefined.

Service worker: unregister only under `window.crossOriginIsolated`. Comment that
this guard is load-bearing — when COOP/COEP do NOT arrive from the origin,
coi-serviceworker.js is the thing providing cross-origin isolation, and blindly
unregistering it forces its register-and-reload dance on every single visit,
i.e. it breaks the fallback path that keeps the InChI WASM working.

`registerLeaveWipe()` keeps listening on `'pagehide'` — preserve the existing
header rationale verbatim (beforeunload is unreliable on mobile and disqualifies
bfcache). In the handler, queue the beacon FIRST when `isLeaveNoTrace()` is true,
then run the wipe: the beacon is the fragile half. Build the URL as
`` `${import.meta.env.BASE_URL}__leave` `` — Vite normalises BASE_URL to a
trailing slash, so no join helper is needed and no deploy path is hardcoded.
Guard on `navigator.sendBeacon` being present.

Rewrite the file header for the widened scope. Keep it referencing the privacy
policy sections so the two stay in step. Record as a comment the accepted wart
that pagehide cannot distinguish a reload from a close (`event.persisted` only
signals bfcache), so a reload with the toggle on purges the cache and
re-downloads roughly 29 MB — and that a Clear-Site-Data storage purge may also
take the flag with it, which is acceptable because the setting is per-visit.

Port the existing tests to the new names and add the cases in `<behavior>`.
Keep the delete-while-walking regression test's intent — it is now trivially
satisfied by `clear()`, so replace it with a case proving a non-prefixed key is
also removed, which is what actually changed.
