## Critical Anti-Patterns

Every row below was discovered by being wrong first, in this session. They are all
about the same failure: concluding from a proxy signal instead of the real one.

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| SIGTERM to headless Chrome does not fire `pagehide` | First on-leave measurement showed nothing wiped at all. Read as "the feature is broken"; actually the wipe never ran, because a signalled shutdown skips `pagehide`. | advisory | Trigger a real navigation away (`Page.navigate` to `about:blank` over CDP) and confirm the beacon in the SERVER log before judging the result. `SIGKILL` is still the right tool for capturing the no-wipe baseline. |
| LevelDB tombstones read as live data | `strings` on `Local Storage/leveldb` still showed `ketcher-opts` after a successful wipe. Deleted keys linger until compaction, so the grep "proved" data survived when it had not. | advisory | Never judge localStorage from disk bytes. Read committed values: a static same-origin probe page that does not load the app bundle, or CDP `DOMStorage.getDOMStorageItems`. Also note grep misses live values entirely — Chromium stores them UTF-16LE, so ASCII grep finds nothing (`strings -a -el`). |
| Cache directory size is not an eviction signal | 18 MB vs 9.3 MB looked like a partial purge. Chrome does not shrink its `sqldb*` blobs on eviction, and the two profiles were also built from different bundles, making the comparison meaningless twice over. | advisory | Count entries for the origin (`grep -ral "<origin>" Cache/Cache_Data`) and check for the specific asset name. Compare against a baseline built from IDENTICAL content. |
| Concluding "config is broken" from a missing tool | Reported three settings files as BROKEN during the /doctor run. `jq` is not installed on this machine; every file parses fine. | advisory | Verify the tool exists before believing its failure (`command -v jq`). Node one-liners with `JSON.parse` are the dependency-free fallback used throughout this session. |
| Assuming one deployment target | All on-leave work was measured against the nginx container while GitHub Pages was still live and publishing on every push to master. The nginx-only measurement was structurally incapable of seeing the Pages failure modes. | blocking | Before claiming ANY header- or endpoint-dependent behaviour works, enumerate every live deploy target (`ls .github/workflows/`, check for `gh-pages` on the remote, read the deploy docs) and state which ones the measurement covers. |
| `# syntax=docker/dockerfile:1` needs the network | `docker build` failed once with an `auth.docker.io` DNS timeout, before parsing a single line, then succeeded unchanged. BuildKit fetches its frontend image first; on WSL2 that host resolves IPv6-only and intermittently times out. | advisory | Nothing in this Dockerfile needs the directive (no heredocs, no `--mount`, no `COPY --link`). Deleting line 1 removes the network dependency. Not done — offered and not taken up. |

<decisions_made>

- **The purge is unconditional; no opt-in.** Shipped first as a footer checkbox, then
  removed on instruction. A setting defaulting to "keep the data" is one almost nobody
  changes, and the policy would then describe the minority case. Accepted cost: every
  reload re-downloads the bundle.
- **Deleted the Pages workflow instead of fixing the code for both targets.** Pages had
  no `__leave` endpoint (purge silently no-op) and, because isolation came from
  coi-serviceworker there, `crossOriginIsolated` was true BECAUSE the worker was
  registered — the unregister guard would have destroyed the very worker providing
  isolation, on every visit. One target retires both bugs with no code change.
- **Kept `coi-serviceworker.js`** as an inert fallback; nginx sets the headers so it
  returns early and never registers.
- **No megabyte figure in privacy 3(4).** The inherited "29 MB" was never measured;
  the build is 49.2 MB uncompressed (18.4 MB deliberately-uncompressed WASM).
- **Left `.planning/PROJECT.md` and `research/STACK.md` untrimmed** — they are archives.
  Consequence: the CLAUDE.md trim is **not durable**; GSD regenerates those sections.

<context>
The thread began as "how can I measure that nothing is left on the client after I leave
the page" and turned into building the removal it was asking about. The habit worth
keeping is the one in the anti-pattern table: every claim here was checked against
something runnable — a real browser profile, a real nginx container, a real server log
— rather than reasoned from the config. Three conclusions were wrong on first pass and
only caught that way, and the largest finding of the session (a second live deployment
that silently broke both halves of the feature) came from a /doctor run, not from the
feature work itself.

The honest summary of the privacy position: everything the site stores is deleted on
leaving, the cache is cleared too where the browser supports it, and history is never
removable. "Nothing whatsoever remains" would be an overclaim, and 3(3)/(4) are worded
to avoid it.
</context>
