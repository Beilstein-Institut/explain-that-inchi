<remaining_work>

**The b-layer is modelled as if it were the t-layer.** Diagnosed, never fixed — the sharpest open
piece of work, and a correctness defect rather than polish.

`ParityText` (`src/components/LayerText.tsx:426-453`) serves both `t` and `b` through one regex,
`/(\d+)([-+?])/g`, which matches only a number *followed by a sign*. In `b2-1+` that matches `1+`
and emits `{kind:'stereo', atom:1}`, swallowing the leading `2` as inert text. But `b2-1+` names a
**double bond between atoms 2 and 1**, not a stereocentre at atom 1. So the `2` is not hoverable at
all, and what the `1` reports is the wrong kind of thing.

Fixture (real, measured): `InChI=1S/C4H4O4/c5-3(6)1-2-4(7)8/h1-2H,(H,5,6)(H,7,8)/b2-1+` — fumaric
acid. Its sibling maleic acid differs by one sign character and is kept in the parser fixtures
precisely as the sharpest check that the b-layer sign is parsed at all.

Note the shape of the fix likely mirrors `07a303c`: a b-layer token needs its own `SubHover` kind
describing a *bond between two atoms*, the way `'siblings'` describes a pair of unbonded atoms.
</remaining_work>

<decisions_made>

- `--line` stays soft at 1.37:1; a separate `--line-control` carries the 3:1 boundary. WCAG 1.4.11
  covers UI components, not container edges. Darkening `--line` globally would coarsen 25 container
  borders for no standards gain; darkening the pills' *fill* instead would break `--ink-soft`'s
  4.5:1 on top of it. `tokenContrast.test.ts` asserts both directions, including that `--line` is
  deliberately **under** 3:1 — so the distinction reads as intent, not oversight.
- Absent legend rows keep 4.5:1 and separate by shape and weight. They are focusable and open their
  own card, so they are *active* controls and 1.4.3's incidental-text exception does not apply.
  `--ink-faint` is 5.20:1 on the card; the lightest AA-legal value is L=0.56 at 4.58:1 — a barely
  perceptible gain for the last of the headroom, so the effect went into a hollow swatch ring instead.
- The Dockerfile now gzips `.wasm`, overriding a decision documented in two files. Both excluded it
  to protect streaming compilation, which cost nothing while the wasm was inlined and never fetched.
  Fetched for real, the exclusion would ship 11.8 MB uncompressed — **worse** than the 7.17 MB of
  gzipped base64 it replaces. `Content-Encoding` is transfer-level; the emitted worker was verified
  to use `instantiateStreaming` with an ArrayBuffer fallback.
- Touch target size follows `(pointer: coarse)`; layout still follows `max-width`. Enumerated per
  control, **not** as a `button` base rule — the InChI layer chunks are inline spans carrying
  `role="button"` from `lib/keyboardProps`, so a blanket `min-height` would inflate the line boxes
  of the string the page is about.
- `src/testing/cssProbe.ts` landed with the first CSS-invariant test rather than in the polish commit.
- The unmatchable `.ketcher .toolbar` rules were deleted rather than wired up: making them work
  changes how the editor looks, which is redesign, not the cleanup pass that found them.
</decisions_made>
