## Critical Anti-Patterns

Rows 1–6 are carried from the 260811-b69 session and still apply — they were all
discovered by being wrong first. Row 7 is from this session.

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Assuming one deployment target | All on-leave work was measured against the nginx container while GitHub Pages was still live. The nginx-only measurement was structurally incapable of seeing the Pages failure modes. Still live: the workflow is deleted but the `gh-pages` branch is not. | blocking | Before claiming ANY header- or endpoint-dependent behaviour works, enumerate every live deploy target (`ls .github/workflows/`, check for `gh-pages` on the remote, read the deploy docs) and state which ones the measurement covers. |
| SIGTERM to headless Chrome does not fire `pagehide` | First on-leave measurement showed nothing wiped. Read as "the feature is broken"; actually the wipe never ran. | advisory | Trigger a real navigation away (`Page.navigate` to `about:blank` over CDP) and confirm the beacon in the SERVER log before judging. `SIGKILL` is still right for capturing the no-wipe baseline. |
| LevelDB tombstones read as live data | `strings` on `Local Storage/leveldb` still showed `ketcher-opts` after a successful wipe. Deleted keys linger until compaction. | advisory | Never judge localStorage from disk bytes. Read committed values via a same-origin probe page or CDP `DOMStorage.getDOMStorageItems`. Chromium stores values UTF-16LE, so ASCII grep misses live ones entirely (`strings -a -el`). |
| Cache directory size is not an eviction signal | 18 MB vs 9.3 MB looked like a partial purge; Chrome does not shrink `sqldb*` blobs on eviction, and the profiles came from different bundles. | advisory | Count entries for the origin (`grep -ral "<origin>" Cache/Cache_Data`) and check for the specific asset name, against a baseline built from IDENTICAL content. |
| Concluding "config is broken" from a missing tool | Three settings files reported BROKEN during /doctor; `jq` is simply not installed here. | advisory | Verify the tool exists before believing its failure (`command -v jq`). Node one-liners with `JSON.parse` are the dependency-free fallback. |
| `# syntax=docker/dockerfile:1` needs the network | `docker build` failed once with an `auth.docker.io` DNS timeout before parsing a line, then succeeded unchanged. | advisory | Nothing in this Dockerfile needs the directive. Deleting line 1 removes the network dependency. Offered, not taken up. |
| Auditing docs against the previous session's notes | The two gaps found today were both invisible from the handoff and the STATE decisions — they only appeared by reading `public/`, `index.html`, `package.json` and `leaveWipe.ts` directly. A handoff records what was decided, not what shipped. | advisory | Audit legal/marketing text against the source tree and the build output, never against planning artifacts. |
