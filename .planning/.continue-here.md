<key_findings>
Root problem to design around: **InChI was built to be machine-read, not human-read** (unlike
SMILES). That gap is the app's entire reason to exist. The literature already standardizes the
**"onion / layers"** analogy — lean into it.

**Six ranked, actionable feature ideas (highest leverage first):**
1. **"Plain English" sentence rendering** of the whole InChI (regex-explainer pattern). Highest
   leverage; the parse tree already exists, so this is a rendering layer. Directly attacks the
   "not human-readable" complaint. → Strong candidate for a first spike/prototype.
2. **Reframe UI around the onion model with progressive layer reveal** — only explain layers the
   current molecule actually produces; collapse exotic ones (`i`, `q`, `m`) by default.
3. **3-step value-first onboarding** opening on a pre-loaded molecule (no long tour; 3-step tours
   hit 72% completion).
4. **"Read your first InChI" guided lesson** using faded worked examples (water/ethanol →
   predict-then-reveal → unaided).
5. **Jargon glossary with accessible tooltips** (≤150 chars, `aria-describedby`, keyboard/focus/
   dismiss) — satisfies WCAG 3.1.3/3.1.4 and lowers cognitive load.
6. **"Simple vs Full" detail toggle** to hide isotope/charge/fixed-H layers novices don't need.

Caveat: little published pedagogy exists specifically for teaching InChI to novices — the app is
filling an under-served niche, so it'll partly set the pattern rather than follow one.
</key_findings>
