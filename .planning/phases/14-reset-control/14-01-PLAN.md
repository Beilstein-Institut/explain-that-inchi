<objective>
Add a Reset control that clears the Ketcher canvas and returns all app state to its
empty/idle placeholder in a single click, without remounting the Editor or recreating
the WASM provider.

Purpose: Lets a user wipe their current exploration and start fresh without reloading
the page — completing the "enter/explore/reset" cycle described in the Phase 14 goal.

Output:
- `resetAll` action added to the Zustand store (atomically clears data + hover fields)
- `KetcherPanel` receives an `onResetClick` prop and renders a Reset button to the
  LEFT of the Send feedback button inside the existing section-label flex row
- `handleReset` callback in `App.tsx` calls `ketcher.setMolecule('')` then
  `useInchiStore.getState().resetAll()` (hover fields need explicit reset because the
  change-handler's `setInchiData` path clears data fields but not hover fields)
- CSS rule `.reset-trigger` added to `styles.css` mirroring `.feedback-trigger` style
  with a neutral/subdued colour (var(--ink-soft) background, var(--bg-canvas) text)
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-01 | Denial of Service | handleReset async function | accept | Reset calls setMolecule('') which is a local WASM operation; no network, no persistence, no unbounded loop. A rapid button-spam is harmless — each call resets to empty and the Ketcher WASM handles idempotent clear correctly. |
| T-14-02 | Tampering | Zustand store state | accept | resetAll() writes only the store's own fields to their defined idle values; no external data is consumed. The store is in-memory only, cleared on page reload, and contains no secrets or PII. |
| T-14-03 | Information Disclosure | None applicable | accept | Reset is a local clear-to-empty operation. No data leaves the browser. No network calls, no persistence, no user-input parsing. |
| T-14-SC | Tampering | npm/pip/cargo installs | accept | Phase 14 introduces no new npm dependencies. No package install tasks; slopcheck not triggered. |

Note: This is a no-backend, client-only static web app. Reset is a local "clear canvas +
reset in-memory state" action. The attack surface is minimal: the only trust boundary is a
user clicking their own browser's button, which triggers WASM operations on their own machine
and writes to in-memory state. No credentials, no PII, no network, no persistence.
