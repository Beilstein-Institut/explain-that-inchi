# Phase 10 — UI Design Contract

> Visual and interaction contract for the feedback toolbar pill + native `<dialog>` modal.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of truth for all visual tokens:** `src/styles.css` (the canonical oklch token
> system, ~60+ custom properties, IBM Plex Sans/Serif/Mono). This phase introduces NO new
> palette, type scale, or spacing scale — it composes the existing tokens. The two genuinely
> missing tokens are called out explicitly under "Token Additions" below.

## Spacing Scale

The project follows an effective ~4px-based scale, used loosely (the design handoff includes
some half-steps like 10/14/18/22px). New Phase 10 UI MUST use multiples of 4 from the column
below; the listed odd values are pre-existing handoff values reused only to match neighbouring
components exactly (e.g. card padding `22px 24px`, gap `18px`).

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Radio-to-label gap, inline icon gap, focus-outline offset |
| sm | 8px | Compact stack gaps (label → control), pill icon-to-text gap |
| md | 16px | Dialog inner section gaps, pill horizontal padding |
| lg | 24px | Dialog body padding (matches card `22-24px`); toolbar row vertical rhythm |
| xl | 32px | (reserve) large layout gaps — not expected in the dialog |

Phase-specific dimensions (match existing components, not new scale values):
- Toolbar row: `margin-top` 0 from Header, sits between `<Header>` (mb 16px) and KetcherPanel; row itself uses `padding: 4px 2px` and `margin-bottom: 12px` (mirrors `.inchiSection`/`.explain` `margin-top: 12px` rhythm).
- Pill button height: 32px (touch-comfortable, < the 38px Ketcher tool size so it reads as secondary chrome, not a primary canvas control).
- Dialog max-width: 560px (narrower than the 1240px app shell; centered by `<dialog>` default).
- Dialog body padding: `24px` (aligns with `.card` `22px 24px`).
- Context-preview block padding: `10px 12px` (verbatim `.layerEg` value — the preview reuses that exact code-block treatment).

Exceptions: none beyond the documented reuse of handoff half-steps (10/12/18/22px) for visual continuity with adjacent components.

## Typography

All sizes/weights below already exist in `src/styles.css`. Phase 10 reuses them; it introduces
no new type tokens. Max distinct sizes in the dialog: 4 — exactly the four system sizes 26 / 14.5 / 12.5 / 10.5px (display title, body, mono/pill chrome, micro-label).

| Role | Size | Weight | Line Height | Family | Token precedent |
|------|------|--------|-------------|--------|-----------------|
| Dialog title (Display) | 26px | 500 | 1.15 | `--font-serif` | `.explain .layer-title` (verbatim) |
| Body / message text / radio labels | 14.5px | 400 | 1.55 | `--font-sans` | `.explain .layer-body` (verbatim) |
| Section / field micro-label (uppercase) | 10.5px | 400 | 1.4 | `--font-mono` | `.section-label` / `.inchiSection .sectionLabel` |
| Pill button label | 12.5px | 500 | 1 | `--font-sans` | `.layer-eg` / `.legendTip` body size (chrome reads fine at this size) |
| Context preview (monospace block) | 12.5px | 400 | 1.5 | `--font-mono` | `.explain .layer-eg` (verbatim) |
| Inline public-issue note | 12.5px | 400 | 1.55 | `--font-sans` | matches `.legendTip` body size |

Weights used: exactly **400 (regular)** and **500 (medium)** — the only weights in the existing
system (no 600/700 except the pre-existing mono `.key`/`.prefix` accents, which Phase 10 does not need).

Heading line-height 1.15 and body line-height 1.55 are the established project values (NOT the
generic 1.2/1.5 defaults) — use them to stay on-brand.

## Color

This is a warm-paper light theme. The 60/30/10 split maps to the existing tokens:

| Role | Token (oklch) | Usage in this phase |
|------|---------------|---------------------|
| Dominant (60%) | `--bg` `oklch(0.985 0.005 85)` / `--bg-canvas` `oklch(0.995 0.003 85)` | Page behind the dialog; dialog surface uses `--bg-canvas` (matches `.card`, `.inchiDisplay`). |
| Secondary (30%) | `--bg-panel` `oklch(0.97 0.006 85)` + `--line` `oklch(0.88 0.008 250)` | Context-preview block background (`--bg-panel`, verbatim `.layerEg`); all borders use `--line`; radio rows hover `--line-soft`. |
| Accent (10%) | `--c-formula` `oklch(0.55 0.14 245)` (blue) | Reserved ONLY for: the pill button fill, the dialog submit button fill, focus rings, the selected-radio indicator, and the "Copy full issue body" action. |
| Destructive / warning | `--c-el-O` `oklch(0.55 0.18 25)` (warm red) | Reserved ONLY for the inline public-issue warning note's emphasis (an icon or the bolded word "public"). NOT a destructive-button color — there are no destructive actions in this phase. |

Text tokens: `--ink` (primary text), `--ink-soft` (body prose / secondary), `--ink-faint`
(micro-labels, placeholders, slashes, disabled hints). Backdrop: native `<dialog>::backdrop`
tinted `oklch(0.2 0.015 255 / 0.32)` (derived from the established overlay/shadow ink
`oklch(0.2 0.015 255 / ...)` used in `.legendTip` shadow and `.loadingOverlay`).

**Accent reserved for (explicit):** feedback pill button, dialog submit button, keyboard
focus-visible rings (`--c-formula`, matching `.copyBtn:focus-visible`), the selected radio
indicator dot/ring, and the "Copy full issue body" text/border. Accent is NOT applied to
every interactive element — radio rows, the textarea, and the close affordance use neutral
`--ink`/`--line` treatments and only show `--c-formula` on focus.

**Rationale for choosing `--c-formula` as the action accent:** it is the existing "primary
chemistry" blue already used for the copy button hover/focus in `InchiSection` and for
canonical atom numbers — reusing it keeps the feedback feature visually native rather than
introducing a new brand color.

## Component & Interaction Contract

This phase is more interaction than visuals; the executor needs these behaviors as firmly as
the tokens. All decisions trace to 10-CONTEXT D-01..D-15.

### 1. Toolbar row + pill button (FEED-01, D-01)
- A new thin row between `<Header />` and `<KetcherPanel />` in `App.tsx`'s flat layout. Right-aligned (`display:flex; justify-content:flex-end`).
- Pill button: 32px tall, `border-radius: 999px`, `--c-formula` fill, `--bg-canvas` text, `--font-sans` 12.5px/500. Optional leading 16px inline SVG (speech-bubble) in `currentColor`.
- Hover: lighten fill via `oklch(from var(--c-formula) calc(l + 0.05) c h)` (matches the lightening idiom already in `InchiSection.module.css`). Focus-visible: 2px `--c-formula` outline, 2px offset (verbatim `.copyBtn:focus-visible` pattern).
- Clicking calls `dialogRef.current.showModal()`. MUST NOT remount KetcherPanel or touch the store (D-02). Open/close state is local React state in App (or a tiny `FeedbackToolbar`), never Zustand.

### 2. Native `<dialog>` modal (D-07)
- Use `<dialog>` + `showModal()` / `close()`. Lean on built-ins: Escape-to-close, backdrop, focus trap. Do NOT re-implement these.
- Surface: `--bg-canvas`, `1px solid --line`, `border-radius: 8px` (matches `.inchiDisplay`), `padding: 24px`, `max-width: 560px`, `width: min(560px, calc(100vw - 32px))`. Reset native `<dialog>` default margin to `margin: auto` (centered).
- `::backdrop`: `oklch(0.2 0.015 255 / 0.32)`.
- Vertical stack (gap 16px): title + intro → Category fieldset → Message textarea → Context preview → inline public-issue note → action row (Cancel + Open GitHub issue).

### 3. Category radio list (FEED-02, D-03)
- `<fieldset>` with uppercase mono legend "Category" and 5 stacked `<label><input type="radio" name="category">` rows. No dropdown, no segmented pills.
- Row: `--font-sans` 14.5px, gap 8px between input and text, `padding: 6px 8px`, `border-radius: 4px`, hover `--line-soft` (verbatim `.legendRow`/`.molItem` hover idiom).
- Selected radio accent: `--c-formula` (via `accent-color: var(--c-formula)` on the input — simplest native styling). Default selection: none required; submit is allowed with no selection only if a sensible default category is chosen — **default the selection to `General`** so submit is always valid.

### 4. Message textarea (FEED-03, D-04)
- Full-width `<textarea>`, min 4 rows, `--font-sans` 14.5px/1.55, `--bg-canvas`, `1px solid --line`, `border-radius: 6px`, `padding: 10px 12px`, `resize: vertical`.
- Placeholder text in `--ink-faint`. Focus-visible: 2px `--c-formula` outline, offset 2px.

### 5. Always-visible context preview (FEED-06, D-05, D-15)
- A read-only monospace block reusing the `.layerEg` treatment verbatim: `--font-mono` 12.5px/1.5, `--bg-panel`, `1px solid --line`, `border-radius: 4px`, `padding: 10px 12px`.
- Renders the SAME field set and SAME placeholders as the submitted body: InChI, SMILES, Preset, App version, User agent — using Phase 9 placeholders (`(no structure loaded)`, `(none)`, `(custom molecule)`) when empty.
- Long values (InChI / UA) wrap with `overflow-wrap: anywhere` and a `max-height` ~160px with `overflow-y: auto` so the dialog stays compact.
- The preview text MUST be derived from the same authoritative source as the submission (per D-11 / project rule: never reconstruct strings) — prefer rendering from the builder's full-body output or the captured `FeedbackContext` snapshot, not a hand-built duplicate template.

### 6. Inline public-issue note (FEED-06, D-06)
- Placed directly above/beside the submit button (read at the decision moment), NOT a top banner.
- `--font-sans` 12.5px, `--ink-soft`, the word "public" emphasized in `--c-el-O` (warm red) and/or a small inline warning glyph. One line, calm — informational, not alarming.

### 7. Submit flow (FEED-04 via Phase 9, D-08, D-09, D-10)
- Submit handler: gather `FeedbackContext` in App (verbatim store `inchi`, `await getSmiles()`, preset name, full UA, assembled `v{version} ({shortSha})`), call `buildFeedbackUrl({message, category, context})`.
- Open the result `url` in a new tab via a real user-gesture anchor (`<a target="_blank" rel="noopener">`), clicked synchronously — NO `await` between the click and the open (popup-blocker safe, D-08). The `getSmiles()` await must complete *before* the gesture if needed, or context is pre-captured; the executor preserves the gesture-open guarantee from CONTEXT.
- **Non-truncated (D-09):** after opening, `close()` the dialog AND reset the form (category → `General`, message → empty). Truncation UI is never shown.
- **Truncated (D-10):** dialog STAYS OPEN. Reveal the truncation note + "Copy full issue body" button. User copies, then closes via Cancel/Escape. Reset happens on next open, not automatically.

### 8. "Copy full issue body" (D-10, D-11)
- Only rendered when the last submit returned `truncated: true`.
- Styled as a secondary text/outline action in `--c-formula` (border `1px solid --c-formula`, transparent fill) — visually subordinate to the primary submit.
- Copies the **full untruncated issue body** sourced from the builder module (D-11 — `fullBody` field or sibling export), never re-assembled in the dialog.
- Transient "Copied — now paste it into the issue." confirmation, mirroring the 3s auto-hide "Copied!" pattern already in `InchiSection`.

### 9. Responsive
- The app already collapses at `max-width: 900px`. The dialog `width: min(560px, calc(100vw - 32px))` handles narrow screens. The toolbar pill stays right-aligned. No mol-list interaction needed here.

### 10. Accessibility
- `<dialog>` provides focus trap + Escape natively. Give it `aria-labelledby` pointing at the title.
- Radio group is a real `<fieldset>`/`<legend>`; each option a `<label>`-wrapped `<input>`.
- Textarea has an associated `<label>`. All focusable controls show the `--c-formula` focus-visible ring (2px / offset 2px) consistent with `InchiSection .copyBtn`.
