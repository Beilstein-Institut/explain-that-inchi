<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App → handleFeedbackSubmit | Assembles FeedbackContext from browser/store values and passes to the pure builder. navigator.userAgent and useInchiStore.getState().inchi are read-only; no untrusted user input is introduced here. |
| handleFeedbackSubmit → ketcherRef.current.getSmiles() | Async call to the WASM-backed Ketcher API. Result is the molecule SMILES the user drew; it flows to buildFeedbackUrl which fences it in a code block. |
| Toolbar pill button → dialogRef.current.showModal() | DOM manipulation only; no untrusted data flows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03-01 | Tampering | handleFeedbackSubmit context assembly | accept | All context fields are read-only system values (store state, navigator.userAgent, Ketcher WASM output, Vite defines). No user-supplied text enters this function — message and category flow directly from dialog to buildFeedbackUrl, not assembled here. |
| T-10-03-02 | Denial of Service | getSmiles() throws / rejects | mitigate | Catch block silently sets smiles to undefined; buildFeedbackUrl uses "(none)" placeholder. Submit is never blocked by SMILES failure (D-12 discretion). |
| T-10-03-03 | Information Disclosure | navigator.userAgent in FeedbackContext | accept | UA string is the user's own browser identity; no PII beyond what the browser exposes natively. It flows to buildFeedbackUrl which fences it in a code block. User sees it explicitly in the always-visible context preview (D-05) before submitting. |
| T-10-03-04 | Tampering | KetcherPanel remount risk from App restructure | mitigate | KetcherPanel must remain unconditionally rendered without wrapping conditions. Acceptance criteria include verifying JSX structure preserves KetcherPanel position. The human-verify checkpoint also exercises this. |
| T-10-03-SC | Tampering | npm/build install | accept | No new packages added. App.tsx changes are additive imports and JSX only. |
</threat_model>
