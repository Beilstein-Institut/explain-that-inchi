<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User → textarea message | Untrusted free-text; flows to buildFeedbackUrl which neutralizes @ and wraps in code fence — handled in Phase 9 builder, not re-implemented here. |
| navigator.clipboard.writeText | Writes the fullBody string (sourced from the builder, not from user input) to clipboard — no PII, no server. |
| hidden anchor target="_blank" | Opens a GitHub URL in a new tab — must carry rel="noopener noreferrer" to prevent the opened page gaining a reference to this window. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-02-01 | Tampering | `<a target="_blank">` anchor | mitigate | `rel="noopener noreferrer"` is locked in D-08; executor MUST verify both tokens are present in JSX (acceptance_criteria includes this grep). |
| T-10-02-02 | Information Disclosure | `navigator.clipboard.writeText(fullBody)` | accept | fullBody contains only: user's own message (typed by them), their molecule's InChI/SMILES (already on screen), their browser UA (their own device info), app version (public). No third-party data, no PII beyond what the user already sees. Clipboard API requires user gesture or permission — browser enforces this. |
| T-10-02-03 | Spoofing | User message → GitHub issue body | accept | @ neutralization is applied by the Phase 9 builder (already tested). This plan does not re-implement mention neutralization; it trusts the builder's output. |
| T-10-02-04 | Denial of Service | Clipboard API unavailable | mitigate | clipboardFailed state path reveals a selectable `<pre>` fallback so user can manually copy; submit flow is not blocked. |
| T-10-02-SC | Tampering | npm/vitest install | accept | No new packages installed; @testing-library/react and vitest are already in devDependencies from Phase 9. |
