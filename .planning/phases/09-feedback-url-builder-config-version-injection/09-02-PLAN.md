<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user prose -> GitHub issue body/title | untrusted free-text message is composed into Markdown + a URL that GitHub renders |
| auto-context -> GitHub issue body | InChI/SMILES/UA strings (untrusted punctuation) are composed into Markdown |
| composed string -> GitHub server URL parser | the final URL is consumed by GitHub's ~8 KB server-side cap |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-04 | Spoofing | user message containing @handle | mitigate | Neutralize `@` in user-supplied text (D-12) so submissions cannot accidentally ping/impersonate GitHub users. |
| T-09-05 | Tampering | special chars / unencoded `#` in body | mitigate | Single-pass URLSearchParams encoding (D-11); round-trip tests assert `+ / ; , ( ) # =` and newlines survive and `#` does not truncate the body. |
| T-09-06 | Tampering | Markdown injection via auto-context (InChI/SMILES/UA punctuation, backticks) | mitigate | Wrap all auto-context values in fenced code blocks (D-02) so punctuation is rendered literally, not interpreted as Markdown/mentions. |
| T-09-07 | Denial of service | oversized URL hitting GitHub's ~8 KB cap (silent server truncation) | mitigate | TextEncoder ~7.5 KB budget guard with deterministic drop-SMILES-then-trim-InChI reduction (D-13), validated against the multi-fragment repro; user message never truncated. |
| T-09-SC | Tampering | npm/pip/cargo installs | accept | Zero new dependencies — native URL/URLSearchParams/TextEncoder only; no package install surface this plan. |
</threat_model>
