  </read_first>
  <action>
    Bump `package.json` `version` from `0.0.0` to `1.2.0` (D-08) — single-field change, nothing else.

    In `vite.config.ts`, at module top (before `defineConfig`), resolve two values:
    - Short commit sha: try `execSync('git describe --tags --always')` from `node:child_process`,
      trimmed (the D-10 primary source); on any throw fall back to `process.env.GITHUB_SHA` sliced to
      7 chars; if still empty, the literal `dev` (the D-09/D-10 locked order). Wrap the `git describe`
      call in try/catch so a tag-less / git-less local build degrades cleanly to the dev marker.
      **Tag-collision guard (do not skip):** `git describe --tags --always` returns the BARE TAG NAME
      on an exactly-tagged commit — once `v1.2.0` is tagged this would emit `v1.2.0` as the "commit",
      producing the nonsensical `App: v1.2.0 (v1.2.0)`. So after resolving, if the value does not match
      `/^[0-9a-f]{7,40}$/` (i.e. it is a tag name, not a hash), replace it with `git rev-parse --short HEAD`
      (also try/caught); only then apply the `$GITHUB_SHA` → `dev` fallbacks. The final `__APP_COMMIT__`
      must be a 7+-char hex sha OR the literal `dev` — never a tag name. This preserves D-10's stated
      `git describe` mechanism as the primary source while honoring its "short hash" intent.
    - Package version: read WITHOUT `import pkg from './package.json'` (tsconfig.node.json lacks
      `resolveJsonModule` — confirmed in read_first; do not add it). Use
      `JSON.parse(readFileSync(new URL('./package.json', import.meta.url), 'utf-8')).version` via
      `node:fs`, or `process.env.npm_package_version` as an equivalent. Pick one; the resolved value
      must equal `1.2.0` after the bump.

    Add two entries to the `define` object (Claude's-discretion names per D-09 — use
    `__APP_VERSION__` and `__APP_COMMIT__`): both values MUST be `JSON.stringify(...)`'d strings
    (define is raw text substitution — a bare string injects as an identifier and breaks the bundle).
    `__APP_VERSION__` = the resolved package version (`1.2.0`); `__APP_COMMIT__` = the resolved short
    sha or the dev marker. These globals appear only in our own source, so the `optimizeDeps`
    transform mirror is not required for them; leave the existing processShim mirror untouched.
    Do NOT assemble the `v{ver} ({sha})` display string here — the two raw globals are the contract;
    format assembly is a downstream consumer concern (Phase 10).

    In `src/vite-env.d.ts`, add ambient declarations matching the chosen define key names exactly:
    a `declare const __APP_VERSION__: string;` line and a `declare const __APP_COMMIT__: string;`
    line, so `tsc -b` resolves the injected globals in app source.
  </action>
  <verify>
    <automated>node -e "const p=require('./package.json'); if(p.version!=='1.2.0') process.exit(1)" && grep -q "__APP_VERSION__" vite.config.ts && grep -q "__APP_COMMIT__" vite.config.ts && grep -q "GITHUB_SHA" vite.config.ts && grep -q "declare const __APP_VERSION__" src/vite-env.d.ts && grep -q "declare const __APP_COMMIT__" src/vite-env.d.ts && npx tsc -b</automated>
  </verify>
  <acceptance_criteria>
    - package.json version field equals "1.2.0".
    - vite.config.ts define object contains __APP_VERSION__ and __APP_COMMIT__ keys, both JSON.stringify'd.
    - vite.config.ts references process.env.GITHUB_SHA in the sha-resolution fallback chain.
    - vite.config.ts wraps the git describe call in try/catch with a final 'dev' literal fallback.
    - The resolved __APP_COMMIT__ value matches /^[0-9a-f]{7,40}$/ OR equals 'dev' — never a tag name
      (tag-collision guard re-resolves to `git rev-parse --short HEAD` when describe returns a tag).
    - src/vite-env.d.ts declares both globals as `declare const ...: string`.
    - `npx tsc -b` exits 0 (clean) with the new ambient declarations present.
  </acceptance_criteria>
  <done>
